Provisioning Readiness Notes

  • No shared network needed: The node runs in pure LoRa mode (Wi-Fi and Bluetooth are switched off in firmware). It reaches the backend over LoRaWAN via the gateway and The Things Network, so the node and the server do not need to be on the same network — or even in the same country. What the server needs is to be reachable by TTN's webhook.
  • Arduino firmware: There is no Wi-Fi SSID or password in the sketch. What must match is firmware/lorawan_credentials.h, generated from your .env with python tools/generate_lorawan_credentials.py. Every node is flashed with the identical sketch; only the sensor reads inside do_send() differ.
  • Setup order: Devices self-register on their first uplink, so they can be powered on at any time — no hierarchy is required first. Recommended order: flash and power the node (it appears under Discovered Devices) → create client → site → building → floor → upload maps → optionally draw rooms → place the node from the discovery inbox.
  • Rooms are optional: Placement is anchored to a floor, not a room. A device may be placed directly on a floor with no room assigned. The node receives nothing from the backend — it only transmits; the backend resolves the hierarchy when you place it.
  • Swagger policy: Swagger remains only for developer testing. Normal setup should be completed from the Admin UI.
